# Miles-Chen-DTC 开发规范

相关文档：[技术选型](1-Technical-Stack.md) · [项目说明](../README.md)

一句话定位：保证独立站前端代码可读、可维护、可测试，并让视觉表达服务于品牌体验和实际转化。

## 一、基本原则

- 先确认页面目标和用户路径，再拆分组件和实现交互。
- 保留品牌审美的克制、私密、神秘和材质感，不用通用电商模板替代设计判断。
- 未确认的产品参数、价格、配送和服务不写成真实信息。
- 优先保证移动端、加载性能、可访问性和清晰的购买承接，再增加复杂动效。

## 二、目录与组件

| 目录 | 职责 |
|---|---|
| `app.vue` | 应用入口和全局页面骨架 |
| `pages/` | 页面路由 |
| `components/` | 可复用展示和交互组件 |
| `layouts/` | 多页面共享布局 |
| `composables/` | 可复用 Vue 组合逻辑 |
| `assets/` | 参与构建的样式和素材 |
| `public/` | 直接公开访问的静态文件 |
| `server/` | Nuxt 服务端逻辑 |
| `docs/` | 技术决策与开发规范 |

组件按独立职责、可复用、可测试拆分；页面过长时按视觉区块和交互边界拆分。

## 三、命名与代码风格

- Vue 组件使用 PascalCase，例如 `ProductShowcase.vue`。
- composable 使用 `use` 前缀，例如 `useScrollProgress.ts`。
- 页面文件使用清晰稳定的 Nuxt 路由命名。
- TypeScript 类型使用 PascalCase；变量和函数使用 camelCase。
- CSS 类名优先使用 Tailwind；品牌专属复杂样式放入明确命名的 CSS 文件或组件样式。
- 优先使用 `header`、`main`、`section`、`nav`、`button` 等语义元素。

## 四、样式与动效

- 简单颜色、透明度、位移和 hover 过渡优先使用原生 CSS。
- 需要时间线、滚动联动或复杂产品展示时才引入 GSAP。
- 动效不得阻断阅读、操作或购买，并考虑 `prefers-reduced-motion`。
- 图片、视频和字体需要考虑文件体积、加载优先级和移动端带宽。

## 五、页面与 SEO

- 每个页面保留一个明确的主标题和主要行动目标。
- 页面补齐 title、description、Open Graph 和必要的结构化信息。
- 图片必须有有意义的 `alt`；装饰性图片使用空 alt。
- 首屏先表达品牌和用户价值，再承接产品事实、信任信息和购买动作。

## 六、测试与验证

- 每完成一个页面或核心交互，至少运行 `pnpm build`。
- 关键流程使用 Playwright 覆盖 Chromium、WebKit 和移动端视口；Firefox 按兼容范围补测。
- 重点检查首页加载、导航、产品浏览、CTA、表单、错误状态和移动端布局。
- 同时检查控制台错误、布局溢出和基础性能。

## 七、Git 与变更要求

- 一次提交只解决一个主题，提交信息使用清晰的中文动作表达。
- 不提交密钥、真实客户信息、临时导出物、构建目录和本地缓存。
- 修改依赖时同步提交 `package.json` 和 `pnpm-lock.yaml`。
- 大规模重构前先确认当前页面可运行，并保留可回退的提交节点。

## 八、AI 协作规则

- 修改前先读取相关文件和本规范，不凭文件名猜测结构。
- 不擅自更换技术栈、升级核心依赖或删除用户已有内容。
- 未确认的品牌、产品、价格、库存、评价、支付和物流信息必须标记为示例或待确认。
- 完成代码修改后说明改动范围并运行匹配的验证。
